# Slices: preview-redesign-drop-activity-bar

**Contract:** docs/ai/backlog/todo/2026-05-15.001.preview-redesign-drop-activity-bar/contract.md

Each slice ships a working subset end-to-end: a user (or downstream system) can observe the behaviour change after the slice merges. Slices are ordered so each is independently mergeable in sequence; Slice 1 removes the vestigial Activity Bar surface before Slice 2 rebuilds the Preview HTML, so the redesign never touches a file slated for deletion.

## Slice 2: Preview redesign for legibility, empty-state differentiation, and accessibility
- **Status:** done
- **Satisfies:** S36, S37, S38, S39, S40, S41, S42, S43, S44, S45, S46, S47, S48
- **Scope:**
  - Rebuild the inline style block and the cell rendering in `src/preview/previewHtml.ts` to give row labels, column headers, cell body content, primary buttons, demoted captions, and reload indicators visually distinct treatments (per S36, S38, S39, S44). Use only VS Code theme variables — `--vscode-foreground`, `--vscode-descriptionForeground`, `--vscode-button-background`, `--vscode-button-foreground`, `--vscode-button-hoverBackground`, `--vscode-panel-border`, `--vscode-editorWidget-background`, `--vscode-editorWarning-foreground`, focus-related variables, and equivalents.
  - **Remove every literal colour fallback inside `var()` calls.** The current renderer carries `var(--vscode-panel-border, #555)`, `var(--vscode-editorWidget-background, #2a2a2a)`, `var(--vscode-editorWarning-foreground, #cc8400)`, and `var(--vscode-button-border, transparent)` (the `transparent` keyword fallback is acceptable; the hex fallbacks are not). After the slice, the inline style block contains no hex codes, no named CSS colours (other than `transparent` / `currentColor` / `inherit` where structurally required), and no `rgb()`/`hsl()` values. Every colour reads from a `--vscode-*` variable.
  - Per-cell summary line (S37): each active cell shows a glance-level summary above its detail listing — derive this from the matrix data already produced by `computePreviewMatrix` (e.g. `${plan.length} keys`, `${zoomCommands.length} zoom commands`, plus a reload badge when `cell.requiresReload` is true). The existing detail listings (the per-key `<ul>` and the per-zoom-command `<ul>`) remain present on the same surface — the summary does not replace them.
  - Shorten the action label so it does not repeat the cell's row/column coordinates (S38). Replace the current `Run reset (${modeLabel} at ${scopeStaticLabel})` with a plain `Run reset` label; the cell's row and column already name its coordinates. Style the button using `--vscode-button-background` / `--vscode-button-foreground` (and `--vscode-button-hoverBackground` on hover) so it reads as a button rather than caption text or panel surface.
  - Reload indicator (S39): when `cell.requiresReload` is true, render a clearly visible reload flag (icon, badge, or labelled text element) as part of the cell's summary line — positioned where the reader sees it before locating the "Run reset" button, not after a paragraph of body copy. Use `--vscode-editorWarning-foreground` (or equivalent) for the indicator's colour.
  - Intro copy (S40): replace the current two-sentence paragraph above the matrix with at most one short sentence that sets the read-only expectation and points at the "Run reset" affordance.
  - **Empty-state captions** (S41, S42, S43), derived from existing `PreviewMatrix` data — no new state-detection pass, no new IPC call, no new discovery scan (contract invariant). Use `--vscode-descriptionForeground` (or equivalent demoted theme token) for the caption text. The button is **omitted entirely** on every no-op cell — no disabled `<button>` element is rendered (contract invariant "No active 'Run reset' button on a no-op cell" plus the brief's ratified default for open question 2):
    - **S41 — Structurally-quiet `(fontSize, session)` cell:** show a short demoted caption explaining that Session resets in-memory zoom only and Font size only has no zoom work to perform. This cell is detectable from the matrix data alone: `mode === 'fontSize' && scope === 'session'` (or, equivalently, `plan.length === 0 && zoomCommands.length === 0`).
    - **S42 — Discovery-empty Font size cells `(fontSize, workspace)` / `(fontSize, global)`:** show a short demoted caption explaining that no size-family keys are set at that scope. Detectable from `mode === 'fontSize' && plan.length === 0` (at Workspace or Global).
    - **S43 — Any other no-op cell:** show a short demoted caption derived from the matrix data describing why nothing would change. Detectable from `plan.length === 0 && zoomCommands.length === 0` (after the structurally-quiet pattern above is handled). In the current closed mode set this is rare in practice (Zoom-only and Zoom-and-font-size always run zoom commands at any scope, so they never reach S43 with the current rules) — implement the branch as a generic fallback for completeness rather than a code path the renderer expects to hit often.
  - **Accessibility** (S45, S46, S47, S48):
    - **S45 — theme adaptation:** every text element must be legible under light, dark, and high-contrast themes. Every colour comes from a `--vscode-*` variable. The contract invariant "no literal colours" guards this — re-check after editing.
    - **S46 — keyboard reachability:** every `<button>` element must be reachable in Tab order, show a visible focus indicator from VS Code's focus-related theme variables (e.g. `--vscode-focusBorder` via `outline` or `box-shadow`), and respond to Enter / Space identically to a mouse click. The inline click dispatcher already handles `click` events; verify Enter/Space activation is also routed through `postMessage({ kind: 'run-reset', mode, scope })` — VS Code dispatches `click` events on a `<button>` for Enter/Space by default, so the existing dispatcher should suffice with no new keydown handler.
    - **S47 — assistive technology:** every cell's mode and scope must be conveyed to a screen reader. Keep the table's semantic structure (`<th scope="row">` for mode labels and `<th scope="col">` for scope headers — the existing renderer already does this). Add accessible names where structural roles are insufficient — e.g. an `aria-label` on each "Run reset" button that names the cell's mode and scope (the button's visible label no longer carries them per S38, but assistive tech still needs them), and an `aria-label` (or equivalent) on reload indicators so the badge is not colour-only. The summary line should appear in DOM order before the detail listing so a screen reader reads "3 keys, reload required" before enumerating the keys.
    - **S48 — reduced motion:** introduce no transitions, animations, or motion-bearing decorations. The redesign is permitted to be motion-free entirely. If any motion is introduced (it should not be), gate it behind the absence of `body.vscode-reduce-motion`. The simplest path is to add no CSS transitions or animations at all.
  - **Behavioural invariants the redesign must preserve** (verified by the previous contract's tests, which must continue to pass):
    - **S28 / contract invariant "No writes from opening, refreshing, re-rendering, or closing the Preview":** rendering remains read-only. The byte-equal snapshot test that guards S28 in the previous contract must continue to pass.
    - **S29:** the action path is unchanged. The inline `<script>` remains a thin click dispatcher that posts `{ kind: 'run-reset', mode, scope }` (or the current message shape — check `previewMessage.ts` and keep the exact protocol). The dispatcher does not store state, does not observe the DOM beyond click/keyboard-activation events, and does not define its own action path.
    - **CSP invariant:** `default-src 'none'`, `style-src ${cspSource} 'unsafe-inline'`, nonce-gated inline `<script>`. The webview loads no external fonts, icons, stylesheets, or scripts.
    - **No client-side state invariant:** no selection state, filter state, expand/collapse state, or sort state in the webview.
    - **S35:** exactly three modes; no Custom mode, no user-supplied command IDs, no user-supplied setting keys.
  - Update `src/test/suite/previewHtml.test.ts` to assert the new HTML shape:
    - No hex codes / named-colour values / `rgb()` / `hsl()` in the rendered HTML.
    - Active cells contain a `Run reset` button whose label does NOT contain the mode label or scope label as substrings (S38). The button has an accessible name (e.g. `aria-label`) that includes the mode and scope.
    - No-op cells contain no `<button>` element (S41, S42, S43, invariant).
    - The structurally-quiet `(fontSize, session)` cell, every discovery-empty Font size cell, and any other no-op cell each contain a caption using a demoted theme token reference.
    - Reload-required cells contain a reload indicator with an accessible name in the cell's summary line, positioned in DOM order before the button.
    - The intro copy is at most one sentence.
- **Done when:**
  - S36, S37, S38, S39, S40, S41, S42, S43, S44 pass against the rebuilt `previewHtml.ts`, verified by `src/test/suite/previewHtml.test.ts` assertions plus the manual smoke below.
